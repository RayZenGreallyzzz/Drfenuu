# AetherBolt 0.8.5 — experimental Tor Engine

Uses Guardian Project tor-android 0.4.9.17 from Maven Central. Native Tor starts only on explicit action in its own screen, bound non-exported service, unbound on leaving the activity. No autostart, no background service request. Standard GeckoView browsing and DNS/proxy settings are unchanged. Typed onion URLs are directed to the Tor screen; in-page onion navigations remain blocked.

The check sends only a fixed HTTPS request to check.torproject.org/api/ip over a socket to loopback SOCKS5; domain is sent to SOCKS as a domain name, TLS uses platform trust and hostname checks, no direct fallback. The separate text reader allows exact v3 onion hosts with HTTP(S), bounded text responses, no JS, subresources, cookies or redirect following; HTML converted to plain text. It does not validate the v3 onion checksum locally; Tor rejects invalid addresses. No URL history in this activity. Closing the screen cancels socket and unbinds service. Official Tor Browser can be opened explicitly by package only, no generic onion fallback.

Limitations: NOT Tor Browser, not a guarantee of anonymity; traffic from normal browser sessions is not routed through Tor. No anti-fingerprinting, bridges, new identity, or full embedded web rendering yet. Tor Project recommends official Tor Browser for browsing. Validate on Android 15: real bootstrap, check result, onion text, TLS failures, cancellation, service stop/restart, VPN and proxy interaction. Test native library ABI alignment, size and packaging; no device verification yet. See https://github.com/guardianproject/tor-android and https://support.torproject.org/tor-browser/security/using-tor-with-other-browsers/.
